## Design (how a native item is made)

* `kinds.rs`: every constant of the surface (one module per legacy module), copies. `ties/*` re-export them (one definition).
* `queries/*`: the same function names and signatures as the legacy original, answered from the **typed core** (`ti4-engine-core` `query::*`, `rules::*`, the kernel with `register_all`) or, where the legacy answer is a plain read of the public `GameState` / printed content, a copy of that read. No string rule module is named. A position the core cannot hold (a table with no faction seated, an id the tables do not know) answers the neutral value (0 / empty / false) instead of the legacy string fallback; a seated game on a real map is always held. The one place where that was cheap to keep exact is `queries::factions::fleet_limit` (pool capped by the law, plus the printed Armada), tested.
* `lib.rs` lane-B section: **shell modules** at the final public paths (`ti4_engine::production`, `::combat`, `::technology`, ...): `pub use ti4_engine_legacy::<m>::*` (the facade, removed at D2-9) plus the native items as explicit `pub use`, which shadow the glob. Only items whose types are shared with the legacy crate are exported there. **Items that carry a type the legacy `Observed`/`Game` also speaks stay in `queries` until lane D's swap** (they would make `ti4-rule-bot`/`ti4-host` mix two types): `queries::tactical::{Movable, MoveRoute, movable_into, routes_into}`, `queries::transit::{Cargo, CargoSource, loadable}`, `queries::production::{Spend, available, ProdView}`. At the swap lane D adds, in the shell of each module, the explicit `pub use crate::queries::...` of these (list above) and flips `choice`/`game`.
* `queries::adapter`: copy of the typed `Position`/`SeatReach`/`SeatCache` of the legacy `core_adapter` (the movement reads of the core by string id), `Position::new_owned/set_active_system` (routes towards a system that is not activated). `queries::view::Full`: a position fully loaded but for the map with the full kernel (the hooks of `hooks.direct`).
