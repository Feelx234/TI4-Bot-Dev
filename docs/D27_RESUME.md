## Rules for everybody (R5, R11)

* `crates/ti4-engine` = package **`ti4-engine-legacy`**. `crates/ti4-engine-next` = package **`ti4-engine`**. `crates/ti4-legacy` is an unrelated stub. Always write the package name, and use `-p ti4-engine-legacy` for "the string engine's tests" (4 544 in-source tests, `--test content_ids_resolve`, the examples).
* New features go on `ti4-engine-legacy` AND must be forwarded in `crates/ti4-engine-next/Cargo.toml`.
* The package set of the aliases must stay the same in all five (comment in `.cargo/config.toml`).

## How to merge other branches

No tracked path moved, so every branch that edits `crates/ti4-engine/src/**` merges as before. Trial merges of `core-integration-16` and `core-q-research` (see the report in the hand-back; textual merge clean). A branch that adds new code using `ti4_engine::<legacy module>` in the bridge still compiles (facade); prefer `ti4_engine_legacy::` there. A branch that adds `ti4_engine::` to `crates/ti4-engine/{tests,examples}` or doc tests must write `ti4_engine_legacy::`. Conflicts to expect: only lines in `Cargo.toml`, `.cargo/config.toml`, the bridge `Cargo.toml`/sources (`ti4_engine::x` lines) and the tool scripts above.
