## Outcome

A replayer project is a **recipe**, not a stack of saved games. It names the immutable inputs, the
imported R01 session with the hashes that pin it, and a tree of branches whose decisions are stored
as the same [`ReplayRecord`]s `rebuild` consumes.

New modules `crates/ti4-replayer/src/project.rs` (format and tree) and
`crates/ti4-replayer/src/persistence.rs` (atomic bounded file I/O). One additive line in `ti4-review`:
`pub const ENGINE_COMMIT`, the recorded engine commit promoted from an internal `env!` so anything
replaying a session can check it. R01's session JSON, its HTML export, and its bounds are untouched.

## The format

`ReplayerProject { schema: "r02-replayer-project", version: 1, inputs, source, branches,
next_branch, checksum }`, serialized as JSON (zstd when the path ends in `.zst`, which R01 does the
same way for its own sessions), with a SHA-256 over the payload with the checksum field blank.
`deny_unknown_fields` everywhere, so a file from a future version is a refusal rather than a silent
loss of a field this build cannot see.

`ReplayInputs` is the seven knobs R01 takes (checkpoint, map pool, seed, rotation, profile table,
temperature, diplomacy). `SourceTimeline` records the session path plus the SHA-256 of the session,
the checkpoint and the map pool at import time, the engine commit and content digest R01 recorded,
the frame count and the seating order. A `Branch` carries `id`, `parent`, `origin`
(`Imported` | `Fork { frame }`), a title, the seat modes it wants, **only the answers made on that
branch**, its frame count, a `verified` flag, and an optional UI selection preserved without
interpretation.

### Rules the format enforces, and where

| Rule | Mechanism | Proven by |
| --- | --- | --- |
| Monotonic ids, never reused | `next_branch` only ever advances; `fork` refuses at the bound; validation requires every id below it | `branch_ids_are_monotonic_and_never_reused` (a branch removed from the list does not hand its id back) |
| Immutable parents | `parent` is set at construction and no setter exists; a child always has a higher id than its parent | `siblings_and_nests_share_one_parent`; doctored files refused by `a_missing_parent_or_a_cycle_is_refused` |
| Exactly one parentless source at branch-0 | `validate` requires the parentless set to be exactly `[branch-0]` | same test ("two parentless source branches", "no branches at all") |
| Cycles impossible, and refused if claimed | parents are strictly older than children, and every branch's chain is walked (so a cycle disconnected from the source is caught too) | same test (self-parent, two-node cycle, child older than parent) |
| 128 branches | `MAX_BRANCHES_PER_PROJECT` from R02-001, checked on `fork` and in `validate` | `a_project_holds_at_most_its_branch_bound` (fills the project, then checks the full one is still valid) |
| R01's frame bound per project, across all branches | `total_frames() ≤ MAX_TOTAL_FRAMES` (`ti4_review::MAX_FRAMES`), charged on `fork` **and** `extend` | `the_frame_budget_spans_every_branch` — including a fork that is legal against its own parent and refused because the tree has no room |
| R01's byte bound | `MAX_PROJECT_BYTES = ti4_review::MAX_SESSION_BYTES`, checked before writing, and again on read of both the file and the decompressed stream | `the_byte_bound_is_r01_s_and_is_applied_before_writing` |
| Atomic write | temp file → rename old aside → rename in → drop backup; restore the old file if the swap fails | `an_interrupted_write_leaves_the_previous_project` (a directory planted at the temp path; the previous project reads back unchanged, and no `.tmp`/`.bak` survives a good save) |
| Refuse, never repair | schema, version, unknown fields, checksum, structure and record sanity all run before any state is handed to the caller | `a_malformed_project_is_refused_not_repaired`, `a_foreign_schema_or_version_is_refused`, `a_tampered_payload_is_refused_even_when_it_stays_valid` |
| Hashes authoritative | import hashes the three files and refuses a promised-hash mismatch; `verify_inputs` re-hashes and compares the content digest | `an_import_hashes_what_it_is_given` (swapped checkpoint → `InputChanged`, foreign corpus → `ProvenanceMismatch`, absent file → `MissingInput`) |
| Only verified branches become live | `verified` is set only by `mark_verified`, and `Branch::playable` needs both it and a current `Verification` | `only_a_verified_branch_against_matching_inputs_is_playable`, `only_a_reproduced_fork_becomes_live` |
| The future is retained | forking never touches the parent; each branch stores only its own answers and ancestors are cut at the child's fork frame | `a_prefix_inherits_up_to_the_fork_and_not_beyond` |
| Viewing does not mutate | read paths return references and rebuild the prefix without touching the tree | `reading_a_branch_never_mutates_the_project` (full serialization plus checksum compared) |

### How a prefix is assembled

`prefix(branch)` walks the chain from branch-0 down and takes, from each ancestor, only the answers
strictly before the frame where the next branch on the chain diverged; the branch itself contributes
all of its answers. The result is sorted by `(frame, ask)`, which is the order the engine asks in.

This is what makes branching non-destructive without duplicating anything: a child forked at frame 5
inherits whatever the parent answered before frame 5 — including answers recorded by a human — and
re-answers frame 5 onward. `a_prefix_inherits_up_to_the_fork_and_not_beyond` checks a source that
answered frames 2 (two asks) and 7, a child forked at 5 (inherits 2/0 and 2/1, not 7), the child's own
answers at 5 and 6, and a grandchild forked at 6 which stops at 5.

### Verification is not a feeling

`verify_inputs(base)` re-hashes the checkpoint and map pool the project names, and refuses when the
content corpus recorded at import is not the corpus this build plays with. `Branch::playable` then
requires the branch's own `verified` flag **and** that verification, so a checkpoint swapped after
import takes every branch in the tree out of play.

One judgement call, recorded because it is narrower than the plan's wording: an **engine commit**
mismatch is reported (`Verification::engine_matches`) rather than refused. R01 stamps the repository
commit of the build that ran the session, so refusing on that field would reject every session made
before the most recent commit while proving nothing about replay determinism. The content digest and
the input file hashes *are* enforced, and those are what a replay actually reads. The commit is
surfaced so R02-007 can show it in the tooltip next to a disabled Play.

## End-to-end: file in, branch out

Two tests play real branches rather than hand-built JSON:

- `a_saved_project_rebuilds_what_it_recorded` — run 12 steps with recording, save the session through
  R01's own writer, import it, record the prefix, save the project as `.zst`, read it back, rebuild
  from the loaded script, and compare every frame's fingerprint against what the branch produced.
- `only_a_reproduced_fork_becomes_live` — fork a loaded project, assert it is **not** playable,
  rebuild to the fork frame, mark it verified, assert it is playable.

`a_project_holds_at_most_its_branch_bound`, `the_frame_budget_spans_every_branch` and the malformed
cases are pure JSON and run in milliseconds, so the refusal behaviour stays cheap to test even though
the end-to-end pair needs the engine.

## Deviations and judgement calls

1. **Project format is JSON, zstd only by extension.** The plan suggested `.ti4replay.json.zst`;
   compression is chosen by the file extension exactly as R01 chooses it, so a plain
   `.ti4replay.json` is inspectable without a decoder and a `.zst` one is not special-cased. The
   extension carries no semantics beyond compression — recorded because it is a wire-visible choice.
2. **No timestamps in the project file.** Deterministic behavior must not depend on wall-clock time,
   and a timestamp would make every save a different byte string, which would defeat comparing two
   saves of the same project.
3. **Engine commit is reported, not enforced** (see the verification section above). Content digest
   and input hashes are enforced.
4. **A branch stores only its own answers.** Storing the full inherited prefix on every branch would
   make `git diff`-style inspection meaningless and multiply the file by the tree depth; the cost is
   that `prefix()` walks the chain, which is bounded by 128.
5. **The frame bound is charged against frames a branch claims it covers.** A project stores a recipe
   rather than frames, so the only honest byte accounting is the file itself (charged against R01's
   session bound) plus the frame accounting above. Inventing a per-frame byte charge would be a number
   with no measurement behind it.
6. **`import` takes the inputs separately from the session**, because R01's manifest stores paths that
   are frequently absolute on another machine; the session supplies provenance and frame count, the
   config supplies what will actually be replayed. Both are hashed.

## Verdict

**ACCEPTED.** Branches are monotonic, parented immutably, and non-destructive to the source; the tree
is bounded by 128 branches and R01's frame and byte bounds; the file round-trips, is written
atomically, and refuses malformed, foreign, tampered, oversized, parentless, orphaned and cyclic
contents instead of repairing them; verification is recomputed from the files on disk; and a loaded
project rebuilds the frames it recorded, with the verified flag following the rebuild rather than the
intention.
