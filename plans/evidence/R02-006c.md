## Outcome

The right-hand panel of R01 stopped being a place where facts were computed and thrown away.

`view.rs` now owns:

| --- | --- |
| `StepView` + `step_view(frame)` | step / decision / action counts, round, phase (the reviewer's `{:?}` spelling), active seat, active system, pending, combat round, `agenda_lines` (reroll count, votes, predictions, in that order), error |

## How R01's output was shown unchanged

Same discipline as R02-006b, plus a stronger check this time.

1. **Every fixed string in the old panel still exists** — extracted all string literals from the old
   and new `decision_panel` and diffed: 66 in the old, 33 in the new, and every one of the 33 that
   left is present in `view.rs`. The only exceptions are format-string *spellings* whose rendered
   output is identical:
   - `Chosen rank {rank}/{} · p {chosen_probability:.5} · best p {best:.5}{}` → the panel now
     formats pre-rendered `rank.probability` / `rank.best`, which `decision_rows` produced with
     `{:.5}` — same characters;
   - `Round {} · {:?} · active {}` → `Round {} · {} · active {}` with `step.phase` already
     `format!("{:?}", phase)`;
   - `Selected system {tile}` → `Selected system {system}` in the model;
   - `{:.3}` → `{value:.3}` inside `precision3`.
2. **Widget inventory**: `.show` 4=4, `CollapsingHeader` 2=2, `Grid::new` 1=1, `section` 2=2,
   `section_with_id` 1=1, `stat_badge` 3=3, `ui.collapsing` 5=5, `ui.monospace` 6=6, `ui.small` 4=4,
   `ui.end_row` 2=2, `ui.separator` 2=2, `ui.heading` 1=1, `ui.horizontal_wrapped` 1=1. Three counts
   fall, each because loops replaced repetitions: `ui.colored_label` 3→2 (the green fleet-plan and
   yellow unknown arms became one call with a computed colour), `ui.strong` 11→10 (the two
   "Selected system…" branches became one `ui.strong(&card.title)`), `ui.label` 26→18 (agenda lines,
   action details, and the six metadata lines of the system card became three loops).
3. **Derivations lifted, not rewritten**: the rank sort (by probability, `total_cmp`), the position
   lookup, the `best` fallback, the below-greedy rule (still *rank* based: a tie at the top with the
   choice second still reads "sampled below the greedy choice"), the summary format, the tick rule,
   the feature column formats, the span suffix and the planet-line format all moved as expressions.
4. **R01's 33 unit and 3 semantic golden tests pass unchanged.**

No behavioural difference was found or accepted in this package: unlike the board, the panel's data
was already frame-only, so the model computes what the loop computed.

## The 10 tests (`crates/ti4-review/tests/decision_view.rs`)

Real decisions come from `LiveReview::advance(Step, 12)` on the committed example inputs, and every
row is compared field by field against the `DecisionDetail` the engine recorded. Cases a healthy run
does not produce are made by bending a clone.

| Test | Pin |
| --- | --- |
| `precision_helpers_speak_for_the_missing_ones` | `—` for absent; five places for scores and probabilities; three for feature values; a third is `0.33333`, not `0.33333333` |
| `step_view_reads_the_header_the_reviewer_shows` | Counts, round, phase spelling and active seat match the frame; the em dash for a missing value is the model's, and nothing leaks `None`; reroll/vote/prediction lines in order with exact wording |
| `a_plan_is_not_mistaken_for_a_choice` | The three policy spellings annotate to nothing, `fleet decision` annotates as the fleet plan it is, and an unknown path is preserved verbatim rather than silently reclassified |
| `a_decision_row_carries_the_prompt_the_choice_and_the_rank` | Sequence/player/faction/prompt/path/summary equal the detail; exactly one option ticked and only when the choice is among the offered ones; rank position within 1..=ranked; probability and best equal the five-place rendering of the real numbers; `below_greedy` is exactly `position > 1` |
| `options_render_their_titles_payloads_and_features` | Title equals the reviewer's `✓ label · score X · p Y`; payload present iff non-empty; preview iff present; every feature's name, three-place value, five-place weight or `nonlinear`, contribution or `—` |
| `a_row_survives_the_pieces_a_frame_might_not_have` | No choice → `chosen ERROR`, no rank, nothing ticked; no probabilities → no rank and `p —`; no context → `None`; **a choice outside the offered set is not ranked and ticks nothing** |
| `an_action_in_progress_is_not_history` | The completed summary never points ahead of its own frame; `action_in_progress` wins the title and gains ` · IN PROGRESS` |
| `event_rows_match_the_frame` | Empty frame gives no rows; ids, types, the cancelled suffix, payload JSON, and an empty payload prints `{}` |
| `the_selected_system_card_says_what_it_knows` | Title and coordinate line for a real tile; planet lines with bullets, traits and specialties; an unknown system says metadata is unavailable rather than showing an empty card; dynamic state is JSON only when present |
| `the_models_are_pure_functions_of_the_frame` | Two calls equal; an earlier frame answers with its own decisions rather than the latest |

## Scope note, recorded before implementation

R02-006 was split a/b/c in `plans/EXECUTION_STATE.md`. 006b took the board. This package took the
decision panel and the system card. **`player_panel` (~606 lines) is deferred to R02-006d** rather
than squeezed in here: it is almost entirely manifest and per-player presentation, R02-007 can already
compose an equivalent from the primitives `view` exposes (`section`, `item_section`, `player_color`,
`content_label`), and a rushed extraction of 600 lines would have been the worst kind of "while I was
in there". The parent criterion is unaffected — nothing in this or the previous two packages moves R01
UX, and the player panel still renders from `view` helpers since 006a.

## Judgement calls

1. **`DecisionPath::Other(String)` keeps unknown paths verbatim.** An engine that learns a new path
   name should show up as text in the panel, not be classified as a policy choice by omission.
2. **`below_greedy` is rank-based, not probability-based**, because that is what the reviewer's own
   sentence claims; a probability comparison would quietly disagree with the words above it on a tie.
3. **`has_metadata` is a field rather than "lines is empty"**, because the panel prints `Planets:
   none` for a known system with no planets and *nothing* for an unknown one — a distinction that was
   carried by nesting and is now carried by data.
4. **`json_pretty` keeps the old behaviour of printing the serialisation error** instead of swallowing
   it. A payload that cannot be printed should be visibly broken.
5. **The action-summary search walks the frames the same way R01 did** (in progress, else the nearest
   completed one), so a replayer and the reviewer never disagree about which turn they are describing.
