## The frame fingerprint

`FrameFingerprint::of(frame)` hashes `sha256(version ‖ 0x00 ‖ canonical_json(projection))`, where the
projection binds engine step, decision count, action count, round, phase, active player, whether the
step resolved a choice, whether an action completed, terminal and error state, the new plain-text
events, the structured events with their payloads, and the **whole `GameState`**. Paths, branch
names, UI selection, timestamps, the manifest and the frame's own `index` are excluded, per the plan.

Hashing the state in full rather than field-by-field is deliberate: the plan asks for "canonical
state … pending timing", and the in-flight timing windows, reroll sets and transaction bookkeeping all
live inside `GameState`. Naming sub-fields would silently under-bind the moment the engine grows one.
The version string is inside the digest, so a fingerprint can never be mistaken for one computed under
a different binding — and the unit tests hash a hand-built digest to prove the version is really
folded in, plus key-order independence, field sensitivity, and that an added field is a different
binding rather than a reused digest.

## What the replay guarantees, and where

| Guarantee | Mechanism | Proven by |
| --- | --- | --- |
| The bot is invoked once per prefix choice and its answer discarded | `GateDecision::Replay` → `ControlledDecider` calls the inner decider, throws the result away, returns the recorded option; `Gate::policy_calls()` and `Gate::replayed()` count both sides | `a_forced_prefix_then_auto_play_stays_aligned`, `rebuilt.policy_calls >= rebuilt.replayed` |
| Exact step prefix, automatic frames included | `rebuild()` drives `AdvanceUnit::Step` one step at a time and digests every frame it produces | `an_automatic_prefix_needs_no_records_at_all` (no records at all: 14 frames identical) |
| Every choice validated | `ReplayScript::answer_for` checks actor, prompt, ordered option ids, typed context, recorded answer on offer, then the `ChoiceFingerprint` | `a_tampered_prefix_is_refused_with_a_typed_diagnostic` (six fields, six typed `MismatchKind`s) |
| Every frame validated | each rebuilt frame's digest is compared against the recorded one before the loop continues | `a_tampered_frame_digest_is_refused`, `repeated_rebuilds_are_identical` |
| Never installs snapshot state | no code path takes a `ReviewFrame.state`; the only way forward is `Game::step()` | structural; `rebuild()` never reads `frame.state` |
| Refusal, never a plausible branch | mismatch → typed divergence recorded **and** the engine refuses the step (`IllegalChoice::NotOffered`), the loop stops, and nothing is returned; bounds, cancellation, missing target and engine errors likewise | `bounds_and_cancellation_produce_no_branch`, `a_target_beyond_the_recording_is_refused` |
| Cancellable between bounded batches | the cancel flag is polled before every step | `bounds_and_cancellation_produce_no_branch` |
| Bounds inherited | `RebuildBounds::default()` = R01's `MAX_COMMAND_STEPS` (2,000,000) and `MAX_FRAMES` (1,000,001) | `bounds_and_cancellation_produce_no_branch` with `max_steps: 3` |

**The headline result.** A forced prefix of four recorded choices followed by ordinary Auto play
reproduced a 40-step run **frame for frame**, digests included — the whole `GameState` every time.
That is the evidence that "invoke the policy once and discard its answer" is load-bearing rather than
ceremonial: without that call the sampling stream shifts and the frames after the prefix drift. The
strongest form, `a_terminal_target_rebuilds_exactly`, replays an entire game to its terminal frame and
matches — that single test takes 193 s because the game on these inputs is far longer than the 603-frame
reference session, which is why the rebuild suite is ~200 s rather than ~20 s.

## Where the prefix comes from

`Gate::enable_recording()` makes the gate write a `ReplayRecord` for every settled decision, built
from the **engine's own `Choice`** through `ReplayRecord::record` (R02-001's validator, which refuses
an answer that was not on offer). The tests rebuild from exactly those records.

This is why the prefix is not reconstructed from the reviewer's decision trace. `DecisionDetail` mixes
in synthetic rows (`fleet decision`, `plan stopped`, ids like `package|N`) that were never engine
decisions, and its `context` is a projection rather than the engine's typed context — validating a
rebuild against it would validate a copy of the question, not the question. The trace remains what it
always was: R01's presentation record. `ReplayRecord` is R02's authoritative one, and the frame
fingerprints come from the frames themselves.

## Deviations and judgement calls

1. **The plan's "one narrow engine invariant test" is not in this package.** The operator froze
   `crates/ti4-engine` for R02, so no engine test file was added. The invariant that test was meant to
   protect — that one engine step can raise several decisions — is instead measured and asserted from
   outside: `a_prefix_with_several_asks_in_one_frame_rebuilds_exactly` finds a real frame that raised
   several asks and replays it exactly, and R02-003's measurement (158 asks over 120 steps, worst
   frame 7-10) is recorded in `plans/evidence/R02-003.md`. Nothing about the invariant is assumed; it
   is observed through the public seam.
2. **`Rebuilt` returns the `LiveReview` on the calling thread.** `LiveReview` is not `Send`, so
   `rebuild()` runs where it is called and hands back a review that cannot cross a thread. R02-007's
   branch thread must therefore call `rebuild()` *inside* that thread (or use `Gate::replaying` with
   `LiveBranch`); the alternative — an unsafe `Send` shim around `Rc` — was rejected.
3. **`RebuildTarget::End` stops at the last recorded frame or at the engine's terminal state**, not at
   "as far as it can go". A rebuild is always relative to a recording.
4. **Cancellation is polled per engine step**, the smallest unit the engine offers. The deterministic
   pre-set flag is what the test asserts; a mid-run timer would be a flaky test with no extra
   coverage, since the check is the same statement.
5. **`Refused` answers with an engine refusal, not a panic.** The gate records the typed mismatch and
   the decorator returns `IllegalChoice::NotOffered { chosen: "r02-rebuild-refused", … }`, which the
   engine records as a step error. That is the backstop: even if a caller ignored the returned
   `RebuildError`, the poisoned step makes the branch visibly unusable instead of quietly playable.
6. **Recording is opt-in.** Building a `PendingManualChoice` per ask costs an allocation and a context
   conversion on the hot path, so it is off unless `enable_recording()` is called; a rebuild never
   records, and R02-005 turns it on for the live branch it persists.

## Tests (`crates/ti4-replayer/tests/rebuild.rs`, 12)

| Test | Proves |
| --- | --- |
| `frame_zero_is_a_legitimate_branch_point` | rebuilding to frame 0 with an empty script works and replays nothing |
| `an_automatic_prefix_needs_no_records_at_all` | 14 frames reproduce identically with no records at all (the determinism floor) |
| `a_recorded_decision_prefix_rebuilds_exactly` | a five-choice prefix replays five and matches every frame |
| `a_prefix_with_several_asks_in_one_frame_rebuilds_exactly` | the worst multi-ask frame found in 120 steps replays exactly, every ask in it included |
| `a_forced_prefix_then_auto_play_stays_aligned` | after a forced 4-choice prefix, Auto play matches the original run to its end; `policy_calls >= replayed` |
| `a_terminal_target_rebuilds_exactly` | an entire game to its terminal frame, replayed from its own records, matches (193 s) |
| `a_tampered_prefix_is_refused_with_a_typed_diagnostic` | actor / prompt / options / context / chosen / identity tampering each yields `Diverged` with the matching `MismatchKind` and `index` |
| `a_tampered_frame_digest_is_refused` | a recorded digest that the rebuilt frame does not match yields `FrameMismatch { index }` |
| `a_target_beyond_the_recording_is_refused` | `TargetUnavailable { wanted: 9000, recorded }` |
| `bounds_and_cancellation_produce_no_branch` | `max_steps: 3` yields `BoundsExceeded`, a set cancel flag yields `Cancelled`, and neither returns a branch |
| `repeated_rebuilds_are_identical` | two rebuilds of one prefix agree with each other and with the run |
| `a_manual_prefix_rebuilds_from_its_own_records` | a prefix whose records carry `Provenance::Human` replays into identical frames |

Plus 23 unit tests (`control`, `decider`, `fingerprint`) and the 8 engine-driven live tests from
R02-003, all still passing; `ti4-review`'s 33 unit + 3 semantic golden tests are unchanged.

## Verdict

**ACCEPTED.** A branch rebuilds from immutable inputs and a recorded prefix; every prefix choice and
every frame is validated; the policy is invoked once per prefix choice so later Auto play stays
aligned; frame zero, automatic frames, nested asks, manual prefixes and a whole game to the terminal
frame all reproduce exactly; and tampering, bounds, cancellation, missing targets and engine errors
produce a typed refusal and no branch. The one plan step that would have touched the engine is
recorded as dropped under the operator's freeze, with its invariant covered from outside.
