## Outcome

`crates/ti4-replayer/src/app.rs` (new, ~700 lines with doc) holds the whole replayer interaction
model; `crates/ti4-replayer/tests/app.rs` (new) proves it in 18 tests with a scripted stand-in for a
running branch. The crate exports `pub mod app;` and nothing else changed: `control`, `decider`,
`fingerprint`, `live`, `project`, `persistence` and `rebuild` are used exactly as they were, so this
package adds a consumer of R02-001..005 rather than editing them.

What is in it:

- **`ReplayApp<H>`** — project + verification + current branch + viewed frame per branch + optional
  attached branch + rebuild status + notice line. Generic over the handle so the app is testable with
  no thread, no game and no window.
- **`BranchHandle`** — the six things a running branch answers to (`snapshot`, `set_mode`, `submit`,
  `run`, `pause`, `stop`, `delegate_pending`). `impl BranchHandle for Gate` is the only bridge to the
  engine; it forwards and converts nothing.
- **`PlayBlock`** — nine reasons "Play from this frame" can be unavailable, each with a
  `tooltip()` sentence written for someone who has not read this module.
- **`PlayPlan` / `RebuildOutcome` / `RebuildStatus`** — Play prepares a fork and hands back what the
  caller must rebuild on its own thread; the app tracks running / done / failed.
- **`ReplaySettings` + `SETTINGS_PATH`** — `out/replays/replayer-settings.json`, atomic write,
  unreadable or unknown-shaped files fall back to defaults.
- **`BranchNode` / `tree()`** — the branch selector's rows, including `playable`, which is
  `Branch::playable(&Verification)` from R02-005 and nothing looser.

## Why the package was split, recorded before implementation

R02-007 as planned is `src/{main.rs,gui.rs,settings.rs}` plus two release builds plus a Windows
smoke pass with screenshots. That is two different kinds of work: deciding what a click means, and
painting. It is also the only R02 package whose planned test list cannot be run in this environment
as written, because a smoke pass needs a desktop session.

The split keeps the parent's acceptance criterion whole across the children and makes the half that
can be proved *here* the half that carries the rules:

- **007a** takes every rule in the plan's `Rules:` and `Tests:` lines — disable buttons after submit,
  explain every disabled Play state, never overwrite R01 settings, navigation never branches, branch
  retains future, safe close while rebuilding, separate settings — and implements them as data with
  tests. The plan's own word for this layer is *GUI reducer states*.
- **007b** is then the shell: `main.rs`, `gui.rs` drawing `ti4_review::view` models (R02-006a/b/c),
  the release builds, and the operator-run smoke pass with screenshots. If a rule is wrong in 007b,
  it can only be wrong in the drawing, not in the decision.

Nothing was deferred silently: the Play tooltip *string* is in 007a; the tooltip *widget* is 007b.

## Findings this package produced

Three rules were wrong in the first draft and are now right, each caught by a test rather than by
reading:

1. **`LiveState::Ready` must not block Play.** The first `play_check` used `LiveState::accepts_run()`,
   which is `Ready | Running | WaitingForHuman`. That refuses Play for a branch that is attached and
   has never advanced — the state a reader is in immediately after importing and starting — i.e. it
   refused the package's own headline feature. Play is blocked only by a branch that could still
   move: `Running | WaitingForHuman`. (`crates/ti4-replayer/src/app.rs:play_check`, comment in place.)
2. **A failed rebuild must not jam Play.** The first draft blocked on `rebuild != Idle`, so one
   refused fork disabled the button for the rest of the session. Only `RebuildStatus::Running` blocks;
   `Done` and `Failed` stay visible as status text and cost nothing.
3. **An empty timeline has no tip.** `at_tip` compared `viewed == len - 1` and so called a branch
   with zero frames "at the tip". It now requires `frames > 0`. This matters because the live-tip
   marker is the plan's device for telling the reader whether they are looking at what happens next.

| Test | What it pins |
| --- | --- |
| `six_seats_toggle_without_disturbing_each_other` | Six chips flip independently; the intent is stored on the branch so the next run starts the same way |
| `a_seat_returned_to_auto_lets_the_policy_answer_the_parked_choice` | `ModeEffect::ReleasedBot` closes the panel and the app says so in words |
| `an_answer_closes_the_panel_and_a_second_click_is_refused` | Accepted answer hides the panel; a repeat click is `Duplicate` at the app, before the branch is asked |
| `a_click_aimed_at_a_choice_that_moved_is_refused_and_the_panel_redraws` | `Stale { current }` reaches the caller intact and the panel shows the choice actually pending |
| `a_seat_can_let_the_policy_answer_just_this_once` | Delegation answers one decision and leaves the seat manual |
| `run_pause_and_stop_reach_the_branch_and_nothing_else` | One goal, one pause, no secret stop; a pause is a request, so state stays `Running`; detaching stops |
| `an_answer_with_nothing_running_is_simply_refused` | No branch attached ⇒ `NoPendingChoice`, with a sentence |
| `looking_through_history_does_not_branch_anything` | Repeated navigation, including out-of-range and repeats, leaves `ReplayerProject` byte-equal |
| `the_tree_shows_what_a_branch_has_proved` | `playable` follows R02-005's `verified && inputs match`, not "has frames" |
| `switching_branches_stops_the_running_one_and_keeps_seen_frames` | Changing view detaches (and stops) rather than running two branches |
| `play_is_refused_until_the_inputs_and_the_branch_are_proven` | Unverified inputs, unproven branch, running branch, terminal frame each refuse with a different tooltip; all nine `PlayBlock`s talk |
| `play_forks_at_the_viewed_frame_and_asks_for_the_prefix` | The fork is allocated, the plan names the child/parent/frame, the parent keeps 50 frames and `verified` |
| `a_finished_rebuild_becomes_the_view_and_the_parent_stays_whole` | Child becomes view at its tip and verified; parent still has its future and is re-enterable |
| `a_refused_rebuild_leaves_no_branch_behind` | A refused fork is removed, status carries the reason, Play works again |
| `closing_the_window_while_rebuilding_is_safe_and_honest` | `close()` returns what was in flight, drops the half-built fork, stops the branch, is idempotent |
| `cancelling_a_rebuild_stops_it_looking_like_a_branch` | Cancel leaves `Idle` and no orphan branch id in the tree |
| `the_replayer_never_reads_or_writes_the_reviewers_settings` | `SETTINGS_PATH` is under `out/replays`, an existing `out/reviews/reviewer-settings.json` is byte-identical after a save, unknown field and non-JSON both fall back to defaults |
| `frames_arriving_from_a_live_branch_extend_the_view_without_losing_position` | New frames do not yank a reader who is on frame 4; already-seen frames do not duplicate or rewind |

The fake branch is deliberately a *gate-shaped* fake: it releases a parked choice to the policy only
when its own seat goes back to `Auto`, it refuses a submission whose fingerprint is not the one on
screen, and it treats `pause()` as a request. A test that could pass against a stub that always
accepts would not be worth its name.

## Judgement calls

- **The app is generic over `H: BranchHandle` rather than holding `Arc<Gate>`.** `Gate` is
  `Send + Sync`, but tying the reducer to it would force every reducer test to build a gate, and a
  gate needs a decider. One `impl BranchHandle for Gate` in the library is the whole coupling.
- **`plan_play` does not rebuild.** `rebuild()` returns a non-`Send` `LiveReview` (R02-004), so the
  rebuild must run on the thread that will own the branch. The reducer therefore allocates the fork,
  marks itself `Running` and hands back a `PlayPlan`; 007b runs `ti4_replayer::rebuild()` on a worker
  and reports with `finish_rebuild` / `fail_rebuild` / `cancel_rebuild`. This is also what makes
  "safe close while rebuilding" testable at all.
- **A refused or cancelled fork is dropped from the project.** `discard_fork` removes a child with no
  children of its own and never rewinds `next_branch`, so ids are not reused and the tree stays
  valid. This is *not* the pruning the master plan defers: it removes a branch the app created
  seconds earlier and never used, because R02-005's rule is that an unreproduced branch must not sit
  in the tree looking playable.
- **Frames are held per branch in the app, not re-derived from the project.** `ReplayerProject`
  stores a frame *count* (a budget quantity), while the app needs the lightweight `FrameTick`s it has
  actually seen. `tree()` takes the max of the two so a branch never looks shorter than it is.
- **Settings fall back to defaults rather than erroring.** A window size is not worth refusing to
  launch over; a project file is (R02-005), and that distinction is deliberate.
- **`SeatMode` renders with `{:?}`** (`"Manual"`, `"Auto"`) instead of adding a `Display` impl to
  R02-001's `control.rs`. Unit variants make Debug identical; growing a frozen-adjacent module for a
  string was not worth it.

## Scope ledger

- **Engine untouched.** `crates/ti4-engine/**` unmodified; `ti4-review` unmodified by this package.
- **R01 settings untouched**, and a test asserts it.
- **No window in 007a.** The reducer has no egui dependency, which is what makes the plan's reducer
  tests runnable in CI at all.
- **007b still to do**: `src/main.rs`, `src/gui.rs`, the seat-chip / panel / branch-selector /

  be composed from `view::` primitives, which is what R02-006b/c provide.
- **Pre-existing workspace test failures unchanged** (`ti4-bridge` golden corpora missing ×3,
  `ti4-mlp --test smoke_refusals` needing generated vocabulary). Not R02 regressions; not papered
  over. See `plans/evidence/R02-005.md`.
