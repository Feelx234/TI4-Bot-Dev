## Outcome

Three changes, none of which changes what the reviewer does today:

1. **A per-seat injection point in `LiveReview`.** `LiveReview::start_with_control(config, hook)`
   takes `PolicyHook = &dyn Fn(&PlayerId, Box<dyn Decider>) -> Box<dyn Decider>` and applies it once
   per seat on the simulation thread, where the deciders are constructed. `LiveReview::start(config)`
   is now that call with the identity hook.
2. **The decorator can sit under the trace.** `TraceBot` held a concrete `LearnedBot`; it now holds
   `Box<dyn Decider>` plus `Arc<Profile>`, and scores through a free `ti4_policy::consider(profile,
   seen, choice, held)` extracted verbatim from `LearnedBot::consider`, which remains as a one-line
   delegate. The hook's output goes *inside* the trace wrapper, so a decision a person made is still
   recorded with the policy's own scores, probabilities and feature projections. The MLP path needed
   no restructuring: `MlpTraceBot` already held `Box<dyn Decider>` and scores independently.
3. **`ControlledDecider`** in `crates/ti4-replayer/src/decider.rs`: the decorator itself, answering
   for one physical seat from R02-001's control state.

Behaviour preservation was proved twice, by different means, because the first attempt at the golden
caught a real defect in the plan itself (see §What the plan got wrong).

## What the plan got wrong, and the fallbacks that replace errors

- **`TrueSkillSignal` cannot be built by a caller.** The plan's step 1 was to mark
  `LearnedBot::consider` public. That is not enough: `consider` returns
  `BTreeMap<String, ti4_policy::projection::TrueSkillSignal>`, and that struct's fields are private
  with no public constructor in the crate or re-exported from `ti4_policy::lib.rs`, so a caller
  outside `ti4-policy` cannot even name the return type, let alone score with it. The extraction is
  therefore the free function `consider(profile, seen, choice, held) -> (features, scores)`, with
  `TrueSkillSignal` staying internal and `LearnedBot::consider` doing the same mapping as before.
  This is the documented fallback for "an engine invariant blocks the plan's chosen mechanism": the
  plan explicitly allowed preferring a different safe mechanism with evidence.
- **A manual ask with no answer cannot be an engine error.** The plan asked for "the
  controlled-decider error". `IllegalChoice` is a frozen engine enum with no variant for "the
  controller forgot", and misusing `NotOffered` would poison the step and lose the frame. So the
  decorator answers from the policy, *counts it* (`ManualFallbacks::unanswered`) and
  `debug_assert!`s, and the docs say a non-zero count while a person is driving is a controller bug.
  R02-003's controller is what makes the path unreachable. In release this is a counted fallback; the
  unit test that would exercise it returns early under `debug_assertions`.
- **A queued option id that is not on offer** cannot happen while `ChoiceFingerprint` binds the
  ordered ids; if it ever did, the id is passed down as a policy answer and the engine's own
  validation refuses it, rather than this crate inventing a refusal.
- **`ReviewSeat` does not exist in R01**, so the hook keys on the physical `PlayerId`, which is what
  R02-001 keys seat control on anyway. `PendingManualChoice` still carries the branch/frame/ask the UI
  needs, separately.
- **`choose_seeing` on `ControlledDecider` is not unit-exercised.** `SeatObservation::bind` is
  `pub(crate)` — deliberately, it is the hidden-information boundary — so no test outside the engine
  can construct one. Both `Decider` methods route through one private `decide()` and log identically,
  so the untested part is a one-line forwarding call; the bound path is exercised through the engine
  by the integration test in the next package, where the live branch actually pauses. Recorded here
  rather than left to look like coverage.
- **Subtractive alternative rejected.** R01's factory hardcodes the trace wrapper per path today, so
  removing it and building tracing in the caller would also work. It was rejected because the live
  trace wrapper is what produces frames *during* play, not only at save; a caller-side
  reimplementation would be new behaviour to verify, whereas this leaves the production path running
  unchanged and proven byte-identical.

## `ControlledDecider` behaviour

| State | Answers from | Policy consulted | Logged provenance |
| --- | --- | --- | --- |
| Auto | inner | yes | `Policy` |
| Manual, answer queued for this fingerprint | the human's option | no | `Human` |
| Manual, one-shot delegation active | inner, once | yes | `DelegatedToPolicy` |
| Manual, nothing queued | inner, counted | yes | `Policy` + `fallbacks.unanswered` |
| Answer queued for a different offer | inner, counted; the stale answer is dropped | yes | `Policy` + `fallbacks.stale` |

`ManualInbox` holds one answer, keyed by fingerprint, and an answer for a different offer is dropped
and counted rather than lingering to be spent later. `AnswerLog` records `(actor, prompt, chosen,
fingerprint, provenance)` in ask order — the live twin of `ReplayRecord`, which is what a rebuild
needs. A test asserts the decider's fingerprint equals the one `PendingManualChoice` would have
published for the same `Choice`, so the answer a person clicks and the answer the decider accepts
cannot be keyed differently.

No engine file was touched. The engine diff is empty: `git diff --name-only -- crates/ti4-engine`
prints nothing.

## Verdict

**ACCEPTED.** The reviewer's default path is byte-identical to the pre-seam reviewer on two bundles
and matches a committed golden; the identity hook is provably the default path; an override below the
trace changes the recorded choice while keeping the policy's scores, probabilities and feature
projections; and the decorator that will drive manual seats exists with its state machine covered.

allow, each recorded above.
