## Outcome

The board used to be 481 lines of egui in which the questions "what is this system, who owns it, is
the wormhole suppressed, is this tile linked to the selected portal" were answered as local variables
inside a draw loop, and then thrown away. They now live in `view::board_view`, which turns a
`(&ReviewSession, &ReviewFrame, Option<&str>)` into one `TileView` per **visible** tile. `gui.rs`'s
`board()` is 260 lines, and every remaining line is geometry or a stroke.

This is the piece R02-007 needs: a branch frame and a review frame that produce the same `TileView`
produce the same board, and the replayer can build one without owning an `egui` context.

## The model

```text
TileView   system, label, q, r, special_area, fill, color, anomaly_label,
           space_owner, planet_owners, selected, portal_linked, ingress, egress,
           wormholes, units, command_tokens, token_labels, planets
PlanetView meta, owner, purged, color, trait_label, badge, coexisting, attachments, ground
UnitStack  owner, base, damaged, galvanized, count
WormholeView kind, token, suppressed
TileFill   Purged | Fracture | Nexus | Hyperlane | Anomaly | Selected | Plain
```

plus three pure geometry helpers the renderer shares: `tile_fill` (the fill rule, returning which
rule won and its colour), `hex_corners` (the shape every ring is drawn from), `planet_offset` (where
planets sit inside a crowded tile).

Geometry is deliberately **out**: positions depend on the space the window has, meaning depends on the
frame. `TileView` has no `Pos2` in it, which is what "same board at a different size" means.

## How R01's output was shown unchanged

Byte-identity is not available for a rewritten renderer — the code is different code — so this package
uses the strongest evidence that is available, and says so rather than overclaiming:

1. **The renderer's operation inventory is unchanged.** Counted in the old and new `board()`:
   `painter.add` 4 = 4, `painter.text` 8 = 8, `circle_filled` 3 = 3, `circle_stroke` 3 = 3,
   `line_segment` 1 = 1, `draw_fracture_portal` 2 = 2, `draw_unit_symbol` 2 = 2. The one difference is
   `draw_wormhole` 3 → 1: three call sites for printed wormholes, placed tokens and the ion storm
   became one loop over the model's ordered list, and a test asserts a token does not draw before the
   printed hole it would displace.
2. **Every derivation moved as an expression, not a paraphrase.** The fill if-chain, the ship-filtered
   sorted-deduped space owners, the planet-owner list with its purged-planet guard, the three wormhole
   sources with their suppression rules, the unit grouping key, the command tokens, the three token
   labels, the portal-link condition, the purged-label suffix and the planet colour/badge/label rules
   were lifted into `board_view` with their arithmetic untouched.
3. **The decisions are now tested, which they were not.** Below. A rewrite that changed a rule now
   fails a test instead of quietly drawing a different board.
4. `ti4-review`'s 33 unit and 3 semantic golden tests pass unchanged, and the golden compares the
   policy decisions of a real 240-step run, so the crate's behaviour around the renderer is pinned.

**One behavioural difference, recorded.** The old loop re-read `self.selected_tile` on every tile, so
in the single frame in which a click happened, tiles later in the list were still drawn with the
*previous* selection until the next repaint. The model snapshots the selection for the frame, so all
tiles agree. The old behaviour was an artifact of the loop, not a design; the new one is what the
screen settled on one frame later anyway.

## What the 11 tests pin (`crates/ti4-review/tests/board_view.rs`)

| Test | Pin |
| --- | --- |
| `tile_fill_precedence_is_the_order_that_keeps_the_board_truthful` | Exact colour of all seven fills, and that purged beats selection (a highlight must not suggest a system is alive), fracture and nexus beat hyperlane/anomaly/selection, anomaly beats selection, and an unknown special area is not special |
| `hex_corners_are_the_shape_every_ring_is_drawn_from` | Six corners on the radius, first at 30° so a flat edge faces the label, and that the 0.92-scaled ownership ring is exactly that shape scaled |
| `planet_offsets_centre_spread_and_lift` | One centred, two at ±22, three or more on a 19 pitch that is wide enough to read and tighter than the two-planet spread, crowded tiles lift, and an empty tile answers instead of underflowing |
| `unit_stacks_group_by_everything_the_glyph_shows` | Three identical fighters are one stack of three; type, damage, galvanize and owner each split a stack; arrival order cannot change the set; a faction hull resolves to a base the glyph knows |
| `the_board_shows_only_what_the_frame_has` | The Fracture's tiles exist only while it is in play, the nexus depends on the nexus and not on the Fracture, and the same frame answers identically twice |
| `selection_marks_one_tile_and_links_its_portal` | Exactly one tile is selected; an ordinary system links nothing; an ingress token lights every egress tile and nothing else; selecting the exit end finds the entry |
| `control_rings_follow_who_is_actually_there` | One controller paints the thick ring, two paint none (a single controller, not a majority), infantry in space paint none because space control counts ships, planet owners are sorted, and a purged planet stops painting the thin ring while still reporting itself purged, dark and `× ` |
| `a_planet_is_its_owner_s_colour_or_grey` | Across **every** planet on a real board: colour is owner's or grey, and a free world carries no attachment, garrison, coexistence or destroyed mark |
| `a_claimed_world_shows_its_garrison_and_labels` | Claiming a world moves its colour to the owner's, lists coexisting players, counts attachments, and keeps a mech and a damaged infantry as two ground stacks; the trait line is recomputed independently and asserted for every planet, with a separator never standing alone |
| `a_suppressed_wormhole_is_still_a_wormhole` | `travel_ban` marks alpha/beta suppressed without removing them, gamma is unaffected, a token on this system joins the list in order after the printed holes, and a token elsewhere stays elsewhere |
| `the_model_is_a_function_of_the_frame` | Two calls are equal; selecting a system changes only selection-derived fields — no planet moved, no fleet moved |

The frames are real setup frames from the committed example inputs, and the state that matters —
ownership, contested space, purged planets, ingress tokens, egress (a property of the map, so set on
the session the test owns), elected laws — is injected. Injecting it is what turns "would have passed
on any board" into a test that would fail if the rule changed.

## Judgement calls

1. **Two tests rather than one big one for the board's meaning**, after clippy pointed out the first
   had grown past 100 lines. Cheaper to rerun, cheaper to read the failure.
2. **`space_owner` is `Option<PlayerId>`, not `Vec`** — the renderer's question is "does anybody own
   this space", and answering "who" was the old code's job at draw time. Contested resolves to `None`
   in the model, where a test can see it, rather than in an `if let [owner]` nobody checked.
3. **`planet_offset(…, 0)` returns the one-planet answer** instead of underflowing `count - 1`. The
   renderer cannot ask it, but a public pure function should not answer a silly question by panicking.
4. **`#[allow(clippy::struct_excessive_bools)]` on `TileView`**: selected, portal-linked, ingress and
   egress are four independent facts that combine (a selected system can be an ingress portal), and
   the alternative was a bitfield with worse names.
5. **`planet_owners` keeps the split-ring indexing decision out of the model.** The model returns the
   sorted owners; which edge gets which owner is still the renderer's, because it is a stroke, not a
   meaning.

## Not in this package

the timeline with them. The board was extracted first because the replayer needs a board and because

## Verdict

that has no painter; what it looks like is 260 lines that no longer disagree with it. R02-006c (player
