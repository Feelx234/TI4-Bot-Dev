## Outcome

`crates/ti4-review/src/view.rs` is now the one place the two reviewers get their look from: the seat
palette, the panel chrome, the abbreviations, the anomaly and wormhole styling, the hex geometry and
the unit glyphs. `gui.rs` lost 370 non-blank lines and gained one `use` block. The module is pure —
every item is a function of the data handed to it, with no app state, no `LiveReview`, no clock and no
filesystem — which is what lets R02-007 draw the same frame beside its own controls without importing
the R01 application.

## "Moved, not changed" is measured, not asserted

The risk in this package is invisible drift in a GUI that no test can render. Two mechanical checks
against the committed file answer it directly.

1. **The moved text is identical.** Extract the same 22 items from `git show HEAD:.../gui.rs`,
   normalize whitespace, strip the `pub ` prefixes that `view.rs` adds, and diff against `view.rs`'s
   body: **one hunk, 11 lines**, and that hunk is rustfmt re-wrapping `item_section`'s argument list
   because `pub ` pushed the signature past the width limit. No token of behaviour differs.
2. **`gui.rs` is the old file minus the move.** Take `HEAD`'s `gui.rs`, delete the same spans, delete
   the added `use crate::view::{...}` block from the current file, and diff: **one line**, the removal
   of `use ti4_model::units::Unit;`, which moved with the only function that used it.

Together these say the R01 binary's rendering code is the same code, reached through a path instead of
a lexical neighbor. `R02-006b` will not be able to claim it this cheaply, which is why the cheap part
went first.

## Snapshot tests (`crates/ti4-review/tests/presentation.rs`, 11)

| Test | What it pins |
| --- | --- |
| `the_seat_palette_is_pinned` | All six seat RGBs, that they are mutually distinct, the neutral grey, and that panel text is black on the light fill (colour marks a seat as a swatch, never as the text) |
| `a_seat_maps_to_a_colour_and_wraps_past_six` | `seat0`-`seat5` map to palette order; `seat6` wraps to colour 0 rather than inventing one |
| `anything_that_is_not_a_seat_is_neutral` | `cargo`, `seat`, `seatx`, `seat-1`, `""`, `Seat1` all get the neutral colour — an id that is not a seat must not borrow one |
| `trait_and_specialty_abbreviations_are_pinned` | C/H/I and the dot; G/Y/B/R and the general T; case-insensitivity; and that the first matching rule wins for `red biotic` |
| `anomaly_styles_and_their_precedence_are_pinned` | All five colours and labels, `None` for no anomaly and for an unknown kind, and that scar beats rift beats nova beats nebula beats asteroids — the most restrictive anomaly is the one that decides play |
| `wormhole_glyphs_are_pinned` | α/β/γ/δ with their colours, unknown is grey `?` |
| `polygons_are_regular_and_rotate` | 3/4/5/6-gons: every vertex on the circle, evenly stepped (after `atan2`'s wrap), a quarter turn lands on the next vertex, a fighter's nose points up, a dreadnought's first vertex is due east, and degenerate counts behave |
| `a_unit_reads_as_its_base_type` | The six base hulls resolve to themselves, a faction hull falls back sensibly, and an unknown id is shown as itself |
| `content_labels_show_the_name_then_the_id` | Unknown id → id; and over 100 real records across four categories, every label is either the id or `Name [id]`, never a name equal to the id |
| `planets_merge_onto_a_tile_without_duplicates` | On a real board: printed planets first in tile order, then what the game placed; placing one the tile already prints does not list it twice |
| `a_tile_shows_its_own_system_and_always_the_same_answer` | A placement in another system does not leak onto a tile, the answer is stable across calls, and no tile in the game repeats a planet or loses a printed one |

The last two need a real `ReviewSession` and a real `GameState`, neither of which derives `Default`,
so they come from `LiveReview::start` on the committed example inputs (frame zero, no engine steps,
~0.4 s) and the *placements* are injected by the test. That is stronger than waiting for a game to
explore something: the case is exercised rather than skipped, and it does not depend on how far a run
happened to get.

Two findings came out of writing them, both in the tests rather than the code: the `atan2` step check
needs wrap normalization (a 3-gon from offset 0 has its third vertex at 240°, reported as −120°), and
the R02-002 golden is a semantic **projection**, not a `ReviewSession`, so it cannot be loaded as one —
worth remembering before a later package reaches for it as fixture input.

## Deviations and judgement calls

1. **`pub`, not a re-export shim.** `gui.rs` imports the moved names (`use crate::view::{...}`) rather
   than qualifying every call, so the move is a two-line change in the 2,371 remaining lines and the
   diff stays reviewable. The alternative — `view::player_color(...)` at 60 call sites — would have put
   real churn in the file whose behaviour is supposed to be unchanged.
2. **One `#[allow(clippy::cast_precision_loss)]`** on the geometry test, whose only cast is a polygon's
   side count. The crate itself allows this class of cast for exactly this reason; an integration test
   does not inherit the lib's allows.
3. **`planets_for_tile` keeps its `crate::BoardTile` / `crate::PlanetMeta` spelling**, so the moved body
   stayed byte-identical instead of being tidied into imported names. Cosmetic consistency is not worth
   spending the byte-identity proof above.
4. **`view::PlanetMeta` is not re-exported**; the test names it as `ti4_review::PlanetMeta`. If R02-007
   wants the layer without the crate root, that re-export happens there, with a reason attached.
