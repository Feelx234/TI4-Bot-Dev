# Screenshot artifacts

Reproducible screenshots of UI states, one folder per artifact, one capture script per screenshot.

    cd web
    npm run screenshots -- all     # every folder
    npm run screenshots -- D       # one folder (id or full name)
    npm run screenshots -- AB      # two-letter ids work the same way

## Folder ids

Folders are named `<ID>-<short-name>` and the ids are sequential: `A`, `B`, ... `Z`, then `AA`, `AB`, ... `AZ`, `BA`, and so on. A new folder takes the next free id, which is the one after the highest id that exists on any branch you are going to merge with. Check `git branch -a` (or `git ls-tree -r --name-only <branch> web/e2e/screenshots | grep -E '^web/e2e/screenshots/[A-Z]+-'`) before picking, so two branches do not take the same id. If two branches clash anyway, rename one folder when merging (the id only has to be unique; nothing else refers to it). The runner matches folders by `^[A-Z]{1,2}-`, so ids go up to `ZZ`; extend the pattern in `_shared/run.mjs` if that is ever not enough.

Each folder holds `capture-*.ts` (Playwright specs), `manifest.json` (title, description, one caption per shot), `out/*.png` and a generated, self-contained `index.html` (ignored by git; rebuilt by the runner).

Shared parts in `_shared/`:

| File | Purpose |
|---|---|
| `mockGame.ts` | `openMockedGame(page, { choice, board, players, events, ... })` renders the real app at `/games/<id>` against routed HTTP and websocket, no backend |
| `fixtures.ts` | gallery board and players, activation options, completed combat, event log helpers |
| `players.ts` | the viewing player with a private hand, and the opponent |
| `shot.ts` | `shot()` writes `<folder>/out/<name>.png` with animations off |
| `hover.ts` | `hoverShot()` hovers, waits for the tooltip and crops around element and tooltip |
| `tooltip.ts` | draws native `title` tooltips, which browsers do not render into screenshots |
| `eventLog.ts` | opens and expands the event log |
| `build-artifact.mjs`, `artifact.tpl.html` | manifest + PNGs to a self-contained page |
| `mockResumable.ts` | `openResumableGame()`: a mocked game whose server can go away and come back (HTTP aborts, websocket closes, status codes, counters) and `sleepAndWake()`; used with `page.clock.install()` for resume-after-idle |
| `mapLobby.ts`, `vite.shots.config.ts` | `openMapLobby()` renders the real lobby and MapPicker against routed HTTP; the watcher-free vite config |
| `run.mjs` | the `npm run screenshots` runner |

Vite runs without its file watcher (`_shared/vite.shots.config.ts`), so a low inotify limit (ENOSPC) does not break the runner.

Fixtures are synthetic, not captured engine states. Playwright starts and stops vite itself (`playwright.config.ts`); set `TI4_SHOT_PORT` to pin the port.

## Real-game shots (BJ-combat-decisions)

`BJ-combat-decisions` holds shots of the real UI taken from real engine games, not mocked fixtures. `capture-real.sh` drives the smoke playthrough (`TI4_SMOKE_SHOT_SUBTYPES`, `TI4_SMOKE_SHOT_DIR` in `e2e/smokePlaythrough.ts`) and commits the PNGs; `capture-committed.ts` only checks that they are present, so `npm run screenshots -- BJ` builds the page from them.

## Hit kind clarity (BK-hit-kind-clarity)

`BK-hit-kind-clarity` shows what each hit decision says now (Assault Cannon, anti-fighter barrage window and Waylay hits, Courageous to the End, Space Cannon under Graviton, bombardment target). The `before-*` PNGs are copies of the real-game BJ captures (the base UI cannot be re-rendered from this branch); the `after-*` PNGs are regenerated by the runner from mocked fixtures.

## Production on a phone (BS-production-phone)

`BS-production-phone` shows the production builder and its payment step in one column on phone sizes, and the total cost on the first dialog. The `before-*` PNGs were taken with `TI4_SHOT_PREFIX=before` on the commit before the change; `npm run screenshots -- BS` regenerates the `after-*` PNGs and asserts one left edge for unit cards and planet rows, 44 px targets, the total and Build button inside the 390x844 viewport, and that the payment panel repeats the builder's total.

## Agenda always visible (BQ-agenda-visible)

`BQ-agenda-visible` shows the agenda strip in every agenda sub-state on phone sizes. The `before-*` PNGs were taken with `TI4_SHOT_PREFIX=before` on the commit before the strip (the captures only log visibility then); `npm run screenshots -- BQ` regenerates the `after-*` PNGs and asserts, per sub-state and size (390x844, 360x740, 844x390, desktop-site), that the agenda name is inside the viewport, not cut off and not covered (`elementFromPoint`). `TI4_SHOT_OUT` moves Playwright's scratch directory off /tmp.

## Technology second pick (BT-tech-second-pick)

`BT-tech-second-pick` shows the Technology primary with 4 and with 6 resources (desktop and 390x844): with 4, the other cards are dimmed with a reason, a hint sits next to "Selected" and Confirm stays enabled for the single free pick; with 6, two picks and a Clear second pick button. The `before-*` PNGs were taken with `TI4_SHOT_PREFIX=before` on the commit without the fix; `npm run screenshots -- BT` regenerates the `after-*` PNGs and asserts the behaviour (data-selectable, reason, hint, 44 px targets on the phone). `TI4_SHOT_OUT` moves Playwright's scratch directory off /tmp.

## Movement variant ships (BU-movement-variant-ships)

`BU-movement-variant-ships` shows the tactical movement dialog for a system holding a carrier and a sol_carrier: each row now counts only ships of its exact type (Available: 1, + disabled after one click). The `before-*` PNGs were taken with `TI4_SHOT_PREFIX=before` on the commit without the fix; `npm run screenshots -- BU` regenerates the `after-*` PNGs and asserts the counts. `TI4_SHOT_OUT` moves Playwright's scratch directory off /tmp.

## Move dialog systems (CL-move-dialog-systems)

`CL-move-dialog-systems` shows the tactical movement dialog naming each system as `#<tile> [<name>]` (destination, origins, en-route pickups) and the per-origin All from here button, desktop and 390x844. `npm run screenshots -- CL` asserts the names, the staged counts (every ship, then fighters, space-area and planet ground forces as far as capacity allows), that the button disables once everything is staged, no horizontal scroll on the phone, and that no message reaches the server before Commit Moves.

## Invasion landing defenders (CM-invasion-defenders)

`CM-invasion-defenders` shows the landing tray listing, per planet, the other players' units on it (owner, ground forces by type, PDS, other structures) and the Space Cannon Defense they roll against forces landed there, including PDS II and L4 Disruptors silencing it, desktop and 390x844. `npm run screenshots -- CM` asserts the texts, that the block sits in the planet card and no horizontal scroll on the phone.

## Trade partners and components on a phone (CQ-phone-trade-components)

`CQ-phone-trade-components` shows the action-phase Trade and Components menus on phones (390x844, 360x740, 390x664) and desktop: on phones an open menu is a sheet between the game header and the bar's bottom edge with a Close button, and each component row spells out its printed name, kind and owner, timing, cost and rules text. The `before-*` PNGs were taken with `TI4_SHOT_PREFIX=before` on the commit without the fix and are committed under `before/`; `npm run screenshots -- CQ` regenerates the `after-*` PNGs and asserts that every partner name, Open button and component row is inside the viewport, not covered, at least 44 px tall, and that each component row has rules text.
## Transit Diodes on a phone (CR-transit-diodes-phone)

`CR-transit-diodes-phone` shows Transit Diodes with 13 controlled planets and ground forces on 7 places (options generated like the engine's `transit_options`), before and after the stepwise panel (what moves, where to, Confirm), at 390x844, 360x740 and desktop. The `before-*` PNGs were taken with `TI4_SHOT_PREFIX=before` on the commit before the change; `npm run screenshots -- CR` regenerates the `after-*` PNGs and asserts the panel stays inside the viewport without horizontal scroll, the list scrolls inside it, 44 px targets, the move summary and the submitted option id.
## Agenda result toast (CS-agenda-result-toast)

`CS-agenda-result-toast` shows the corner toast every seat (the voter included) gets when an agenda vote finishes: For wins (a law enters play), Against wins (a directive resolved), an election, a tie and a silent table decided by the speaker, desktop and 390x844. `npm run screenshots -- CS` feeds the engine's `agenda_log` through a mocked state update and asserts the texts, the gold accent, that a later state with the same log does not toast again, and that the toast stays inside the viewport.
